3. MODELS -- pre-download so runs never stall mid-way
--------------------------------------------------------------------------------
Qwen2-VL-2B-Instruct (default backbone) + the DenseNet-121 Grad-CAM classifier
download automatically the first time you run the pipeline (step 5/6 below) --
already cached on this machine.

To also pre-download the paper's other models (Qwen2-VL-7B, LLaVA-1.5-7B, and
a BLIP checkpoint) ahead of time (~30GB total, pure disk cache, no GPU used,
safe to run alongside anything else):

    wsl -d Ubuntu -- bash -lc 'cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && export HF_TOKEN=$(grep HF_TOKEN .env | cut -d= -f2) && python3 scripts/download_all_paper_models.py 2>&1 | tee /tmp/model_download.log'

    Uses the HF_TOKEN saved in .env (gitignored -- never commit that file) to
    get authenticated Hugging Face rate limits, which matters a lot here --
    anonymous downloads of these large multi-GB shards were repeatedly
    stalling partway through. If you ever need to redo the .env file:
        wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && printf 'HF_TOKEN=YOUR_TOKEN_HERE\n' > .env"
    (get a free Read-scope token at huggingface.co/settings/tokens)

    - Qwen2-VL-7B: config.py's VLM_MODEL_NAME can point here for the paper's
      Table 4 "7B" row.
    - LLaVA-1.5-7B: Ammar's track (reasoning_llava.py already targets it).
    - BLIP: weights only -- not yet wired into ablation_study.py as an actual
      text-embedding option (separate follow-up dev work, not just a download).

    Don't load two 7B models onto the GPU at the same time (16GB VRAM) --
    coordinate with Ammar if he's also on this machine.

5. FINE-TUNING COMPARISON (frozen vs LoRA vs QLoRA vs full) -- beyond the paper
--------------------------------------------------------------------------------
The paper's own model (f_theta) is always FROZEN -- Section 3, Eq. 3. This
section is an extension beyond the paper: it fine-tunes LoRA and QLoRA
adapters, and also does a full (every-parameter) fine-tune, all starting
from the same Qwen2-VL-2B backbone, and compares all four regimes side by
side on the exact same metrics (Tables 1-4 style) the paper defines.

Run everything (rerun the frozen baseline with the fixed CheXpert
label-leakage bug, train + evaluate LoRA, train + evaluate QLoRA, train +
evaluate full fine-tuning, compile one comparison report) from Windows
PowerShell:

    $env:N_ABLATION = "1000"
    $env:N_AGENTIC = "50"
    $env:N_FINETUNE_STUDIES = "300"
    $env:EPOCHS = "1"
    $env:RUN_FULL_FT = "1"
    .\run_finetune_pipeline.bat

Full fine-tuning trains ALL ~2B parameters and is by far the most VRAM-
hungry regime, even with gradient checkpointing + an 8-bit optimizer (see
src/vlm/finetune_qwen.py's run_finetune docstring). If it OOMs on your
RTX 5060 Ti, set $env:RUN_FULL_FT = "0" and re-run -- you'll still get the
frozen/LoRA/QLoRA comparison, just without the full-FT row.

Safe to re-run -- each step is skipped if already done (same .setup_markers/
convention as run_master.bat). Steps can also be run one at a time inside
WSL if you want more control:

    wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && python3 run_chexpert_eval.py --model qwen2-vl --n-ablation 1000 --n-agentic 50"
    wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && python3 src/vlm/finetune_qwen.py --regime lora --n-studies 300 --epochs 1"
    wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && python3 run_chexpert_eval.py --model qwen2-vl --n-ablation 1000 --n-agentic 50 --adapter-path models/lora_chexpert_2b --finetune-regime lora"
    wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && python3 src/vlm/finetune_qwen.py --regime qlora --n-studies 300 --epochs 1"
    wsl -d Ubuntu -- bash -lc "cd /mnt/c/Users/cslabadmin/Desktop/research && source .venv/bin/activate && python3 run_chexpert_eval.py --model qwen2-vl --n-ablation 1000 --n-agentic 50 --adapter-path models/qlora_chexpert_2b --finetune-regime qlora"
